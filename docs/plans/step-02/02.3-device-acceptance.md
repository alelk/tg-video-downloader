# Stage 02.3 — Verify physical-device behavior and close out

> below. No physical-device measurements are claimed; see the overview for approved scope.

## Read before starting

Read the overview, previous executor notes and research. 02.2 must pass first; record any
additional approved follow-up fix before starting final acceptance.

## Stage decisions

The actual iPhone Telegram Mini App is the primary acceptance environment. A passing Safari
control or headless WebKit test does not substitute for it. Do not deploy unreviewed changes
merely to test; prepare the matching candidate artifact and use the authorized test environment.

## Checks

Record device/OS/Telegram, launch path, image and asset identity for every result. On the affected
physical iPhone with no external keyboard, require **20/20 successful first taps per repeated
scenario** below, distributed across at least three full close/reopen sessions. “Success” means
the software keyboard is visibly usable and typed characters enter the intended field once.
These are acceptance targets, not measurements already observed.

| Scenario                                                    | Required result                                            |
|-------------------------------------------------------------|------------------------------------------------------------|
| First URL-field tap after fresh Mini App open               | Keyboard on first tap, correct input                       |
| Dismiss keyboard, tap same field while DOM focus may remain | Reopens on first tap                                       |
| Move between two editable fields                            | Correct target and keyboard; no lost/duplicated characters |
| Navigate away/back and reopen a field                       | No stale element/session; first tap works                  |
| Background Telegram and return                              | Input recovers on first tap without reload                 |

Also complete each functional check once per relevant control family (URL, preview metadata,
settings, rule/channel editor and a dialog); repeat if results are intermittent:

- Cyrillic/Latin text, deletion, autocorrect and an available composition/IME keyboard.
- Paste via the iOS menu, caret movement, range selection and replacement.
- Multiline field scrolling; keyboard does not cover the active editing area.
- Numeric/password fields as applicable; values and selection remain correct.
- Form buttons, dropdowns, scrolling and navigation after touches; no duplicate activation.
- Preview → metadata edit → job submission preserves entered values.
- Safari on the same iPhone, Android Telegram if available, and desktop as regression controls.
  Record unavailable secondary platforms explicitly; the affected iPhone remains mandatory.

Verify the candidate image uses the intended published/composite wrapper and fresh assets,
including cache revalidation through the real ingress. Run `./gradlew build` on the final code.
Record baseline failures and candidate results side by side. A resize or `activeElement` equality
alone is not a pass.
