# Stage 01.3 — Статический анализ: Detekt + ktlint с baseline

> Подключить Detekt и ktlint через конвенции так, чтобы новый долг блокировался, а старый был
> записан в baseline. Код приложения не трогаем. Next stage: 01.4.

## Read before starting

- `../step-01-refactoring.md` — G11.
- `.claude/skills/kotlin-project-layout/references/static-analysis.md`,
  `templates/shared/detekt.yml`, `references/convention-plugins.md` (что владеет конвенция).
- Executor notes 01.2.

## Stage decisions

- Detekt и ktlint подключаются в конвенциях `tgvd.kmp`, `tgvd.compose.js` и `tgvd.jvm` (не в корне),
  по main и test исходникам. Для KMP — все source set'ы, которые есть в модулях:
  `commonMain`, `commonTest`, `jvmMain`, `jvmTest`, `jsMain` (wasm-путей из шаблона у нас нет).
- `detekt.yml` в корне — из шаблона скилла. Исключения для test support: `fixtures/`, `fakes/`,
  `Fake*.kt` и весь модуль `domain/domain-test-fixtures` (правила `LongParameterList`,
  `ReturnCount`, `MatchingDeclarationName`).
- Генерированный код (`/build/generated/`, `/generated/compose/`) исключён из ktlint.
- **Baseline** — отдельный на модуль (`detekt-baseline.xml`, `ktlint-baseline.xml`), генерируется
  **один раз в этой стадии** на коде, который не менялся с 01.2. Позже baseline только сокращается;
  перегенерировать, чтобы поглотить новые находки, нельзя.
- Массового переформатирования нет: `ktlintFormat` по всему репозиторию не запускать.
- `@Suppress` в новом коде — только с однострочной причиной.
- Если Detekt 1.23.x падает из-за версии Kotlin на своём classpath — зафиксировать версию Kotlin в
  конфигурации `detekt` на ту, с которой собран Detekt (или взять версию Detekt, поддерживающую
  Kotlin 2.3); решение и причину — в notes.

## Work

1. Добавить плагины Detekt и ktlint в каталог и маркеры в `convention-plugins/build.gradle.kts`.
2. Подключить в конвенциях (по `static-analysis.md`).
3. `detekt.yml` в корень; `.editorconfig` для ktlint, если его нет (стиль — `ktlint_official`,
   если baseline становится несоразмерно большим — `intellij_idea`; выбор и размеры baseline в notes).
4. Сгенерировать baseline для каждого модуля (`detektBaseline`, `ktlintGenerateBaseline` или
   эквивалент плагина).
5. `./gradlew build` — зелёный.

## Checks

```bash
./gradlew build
./gradlew tasks --all | grep -E ':(detekt|ktlintCheck)' | head   # задачи есть во всех модулях
```

- Внести намеренное нарушение (например, неиспользуемый импорт и слишком длинную функцию) в один
  модуль → `./gradlew build` красный → откатить. Записать в notes.

## Done when

- `./gradlew build` запускает Detekt и ktlint во всех 11 модулях; baseline'ы закоммичены вместе со
  стадией; проверка на красное выполнена.

Решения и отклонения:
1. **Стиль `intellij_idea`, а не `ktlint_official`.** При 120 колонках: `ktlint_official` — 4691
   находка, `intellij_idea` — 3211 (на ~21.7 тыс. строк, 354 файла; при 140 колонках — 3879 против
   2592). Разница — правила обёртки, которых нет в `intellij_idea` (`multiline-expression-wrapping`,
   `function-signature`, `class-signature`, `chain-method-continuation`), и которые противоречат
   форматтеру IntelliJ, в котором пишется код: с `ktlint_official` каждое переформатирование в IDE
   давало бы новые находки. Сочтено «несоразмерным» по критерию стадии.
2. **`max_line_length = 120`** — чтобы совпадать с `MaxLineLength` Detekt по умолчанию (шаблон
   `detekt.yml` его не меняет) и правым полем IntelliJ; иначе два инструмента спорили бы о лимите.
3. **Версия Kotlin для Detekt не фиксировалась**: конфигурация `detekt` сама разрешает
   `kotlin-compiler-embeddable:{strictly 2.0.21}`, KGP 2.3.10 её не поднимает, анализ работает.
4. **Исключение генерированного кода из ktlint** расширено: помимо `/generated/compose/` и
   `/build/generated/` исключается всё под `layout.buildDirectory`. Без этого при вынесенном build dir
   (`/home/agent/gradle-out/build/features/generated/buildconfig/…`) `BuildConfig.kt` попадал в
   baseline с путём `../../../../…`; при обычном build dir поведение то же, что в шаблоне.
