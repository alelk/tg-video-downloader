## Stage decisions

- **Правила и каналы** — по паттерну 01.6. Каналы: фильтры `tag` / `channelId`+`extractor`, теги;
  `!!` → `Either` (битый ввод → 400, G10).
- **Workspaces — семантика авторизации сохраняется как есть** (разобрано при планировании 2026-09-29;
  перед правкой сверить с кодом, расхождения — в notes):
  - `GET /workspaces` — workspaces, где вызывающий участник;
  - `POST /workspaces` — создаёт workspace (вызывающий `OWNER`, 201); если slug занят — добавляет
    вызывающего как `MEMBER` и возвращает существующий (200). Это вступление по slug — известный
    риск (Not in), не чинить;
  - `POST /workspaces` с битым slug → `400` с телом `{"error": …}` — побайтно как сейчас;
  - список участников — только участнику (`WorkspaceAccessDenied`); добавить/удалить участника —
    только `OWNER`; `role` из запроса: `"owner"` без учёта регистра → `OWNER`, иначе `MEMBER`.
- **System.**
  - Статус и обновление yt-dlp — через доменный порт `YtDlpService`.
  - Настройки: доменная модель `SystemSettings` и порт `SystemSettingsStore` в domain; его реализует
    `SystemSettingsHolder`. Маппинг `ProxyConfig`/`YtDlpExtractorOverride` ↔ domain — в infra,
    DTO ↔ domain — в `api:mapping`. JSON идентичен (golden `SystemSettingsDto`).
- **Отвязка от infra.** `server:infra` удаляется из зависимостей `server:transport`. Значения
  `TelegramConfig` для auth-плагина передаёт `server:app`; `TelegramAuthValidator` создаётся в
  `server:di`/`server:app`. `transport/util/workspaceAccess.kt` удаляется.
- **Гигиена domain.**
  - `Clock` без дефолтов во всех use-case'ах (сейчас `= Clock.System` в 7 местах); DI:
    `single<Clock> { Clock.System }`; в тестах — `TestClock` из `domain-test-fixtures`.
  - `UnconfiguredLlmPort` в infra: `suggestMetadata` → `Left(DomainError.LlmError("none", "LLM is not configured"))`.
    `PreviewUseCase` принимает `LlmPort` (не nullable). По коду `resolveFallback` на `Left` идёт в тот
    же фолбэк, что и на `null` (`MetadataSource.FALLBACK`) — закрепить тестом «Unconfigured ≡ прежний
    null». Если результат отличается — стоп, notes.
  - `NoopTransactionRunner` → `domain-test-fixtures` (сейчас в `domain/.../tx/TransactionRunner.kt`;
    main-код его не использует — проверить `grep`).
  - Удалить обёртку `api/mapping/.../rule/buildSaveAsRuleRequest.kt`, вызывать доменную
    `domain/job/buildSaveAsRuleRequest.kt`. Потерю `includeCategory` **не** чинить (Not in).
- **Fitness-тесты** (списки `KNOWN_*` пустые с первого дня):
  - `TransportSourceGuardTest` в `server:transport`: нет импортов `….domain.*.*Repository` и
    `….server.infra.*`;
  - `DomainPurityTest` в `domain` (`src/jvmTest`): в `domain/src/commonMain` нет `io.ktor`,
    `org.jetbrains.exposed`, `kotlinx.serialization`, `org.koin`, `Clock.System`; guard: просканировано
