## Stage decisions

- **Порядок старта.** `loadConfig` → `validateConfig` (fail-fast, все ошибки одним сообщением) →
  при `eagerDatabase`: DataSource → Flyway `migrate` → `Database` — до установки Koin и роутинга;
  готовые объекты передаются в Koin-модуль, ленивое создание в `single {}` убирается. Ошибка: в
  `module()` — исключение; в `main` — лог и `exitProcess(1)`.
- **Порядок плагинов:** ContentNegotiation → DefaultHeaders → CallId → CallLogging → CORS →
  StatusPages → Resources → роутинг. `TelegramAuthPlugin` остаётся route-scoped.
- **Health.**
  - `/health` — побайтно прежний (`{"status":"ok"}`, 200, без auth).
  - Новые `/health/live` (всегда 200) и `/health/ready` (`SELECT 1` → 200, иначе 503), оба вне auth,
    тела — по `health-endpoints.md`.
  - `api-surface.txt` обновляется (разрешённое добавление, G1).
- **Жизненный цикл.**
  - Фоновые сервисы (`YtDlpBootstrap` + `JobProcessor`, бот) подписываются через
    `monitor.subscribeFor(this, …)`, если он есть в Ktor 3.4.0 (в публичной документации Ktor его
    нет — проверить компиляцией). Если нет — fallback из `background-services.md`: `subscribe` с
    сохранёнными хэндлами, guard `if (it === this@module)`, `dispose` на `ApplicationStopped`.
    Какой вариант выбран — в notes.
  - Только при `startBackgroundServices = true`.
  - Логика остановки `JobProcessor` здесь не меняется (это 01.9).
- **Fail-fast по токену.**
  - При `devMode=false` отказ стартовать, если `telegram.botToken` пустой или ∈ {`test-token`,
    `dev-token`}; сообщение называет переменную `TELEGRAM_BOT_TOKEN`.
  - Дефолт в `application.yaml`: `${TELEGRAM_BOT_TOKEN:-test-token}` → `${TELEGRAM_BOT_TOKEN:-}`.
    Inline-конфиг compose (там `dev-token` и `devMode` по умолчанию `true`) не трогаем.
  - При `devMode=true` — `WARN`: заголовок `X-Telegram-Init-Data: dev` пропускает без подписи,
    never in production.
- **Allow-list'ы (Fork 5).**
  - Подключить `TELEGRAM_ALLOWED_USER_IDS` и `TELEGRAM_ALLOWED_USERNAMES` в `application.yaml` и в
    inline-конфиг `docker-compose.yaml` (`$${…:-}`); строка через запятую → список.
  - **Мина стадии:** пустая переменная не должна превратиться в список из одной пустой строки —
    иначе `allowedUsernames = {""}` делает allow-list непустым, и 403 получают все. Нормализация:
    trim каждого элемента, пустые отбросить. Где нормализовать (декодер Hoplite, `validateConfig`
    или маппинг в `TelegramAuthConfig`) — выбор исполнителя.
  - Тест привязки через настоящий загрузчик: окружение становится параметром `loadConfig` (дефолт
    `System.getenv()`). Если препроцессор `${…}` Hoplite нельзя переключить на карту — проверить
    дочерним процессом JVM с заданным env; способ — в notes. Случаи: не задано → пусто; `""` →
    пусто; `"1, 2"` → `[1, 2]`; `"@Alice,bob"` → как сейчас обрабатывает плагин.
  - Роут-тест: allow-list `[42]`, запрос от dev-пользователя (id 1) → 403.
  - Оба списка пусты → `WARN` «доступ открыт любому пользователю Telegram»; иначе `INFO` с
    количеством (без самих id).
- **G10.** В `StatusPages`: `BadRequestException`, `ContentTransformationException`/
  `JsonConvertException`, `ParameterConversionException` и ошибки конвертации `Resources` →
  `400` + `ApiErrorDto(code = "VALIDATION_ERROR")`. Ожидания роут-тестов из 01.4 для битого ввода,
  который теперь ловит `StatusPages`, меняются с 500 на 400. Места ручного разбора (`Uuid.parse` в
  `jobRoutes`, `!!` в `channelRoutes`) чинятся и переводят свои ожидания на 400 в 01.6–01.7.
- **Логи.** В паттерн `logback.xml` добавить `%X{correlationId}`. `logging.level`, `logging.format`,
  `jobs.maxAttempts`, `jobs.retryDelayMs` — документировать как «читается, не используется», не
  реализовывать и не удалять.
- **Docker.** Во всех трёх серверных Dockerfile:
  `ENTRYPOINT ["sh","-c","exec java $JAVA_OPTS -jar /app/app.jar"]`.
- **Документация.** `CONFIGURATION.md` (fail-fast, allow-list из env, неиспользуемые ключи),
  `DEPLOYMENT.md` (health live/ready, один инстанс, fail-fast, предупреждение про
  `TELEGRAM_DEV_MODE=true` по умолчанию в compose), `.env.example` — комментарий у allow-list'ов
  остаётся верным.

## Checks

```bash
./gradlew build
grep -c 'exec java' server/app/Dockerfile server/app/Dockerfile.ci Dockerfile.tgvd-server   # по 1
grep -n 'test-token' server/app/src/main/resources/application.yaml                         # пусто
grep -n 'allowedUserIds: \[\]' server/app/src/main/resources/application.yaml docker-compose.yaml   # пусто
```

- Юнит-тесты `validateConfig`: пустой токен при `devMode=false` → ошибка с именем переменной;
  `devMode=true` → ок.
- Тест: в БД заранее создана таблица, конфликтующая с `V1` → `module()` бросает, роутинг не установлен.
- Роут-тесты `/health`, `/health/live`, `/health/ready` (включая 503 при недоступной БД).
- Тесты allow-list'ов (см. мину), роут-тест 403.
