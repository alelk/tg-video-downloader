## Stage decisions

- **Сетка фиксирует текущее поведение, а не желаемое.** Если фактический ответ отличается от
  ожидания в этом файле (например, чужой ресурс даёт не 404), тест утверждает фактическое, а
  расхождение идёт в notes. Исключение одно — битый ввод (G10), его ожидание меняет 01.5.
- **Тестируемый `module()`.** Из `configureApplication` выделяется
  `fun Application.module(config: AppConfig, eagerDatabase: Boolean = true, startBackgroundServices: Boolean = true, overrides: List<Module> = emptyList())`:
  - чистый перенос: порядок плагинов и роутов тот же; `main` вызывает `module(config)`;
    `configureApplication` удаляется;
  - `startBackgroundServices` управляет `YtDlpBootstrap`, `JobProcessor` и
    `TelegramMiniAppAutoReplyBot`;
  - `eagerDatabase` резолвит `Database` из Koin сразу после установки Koin (правильный порядок
    старта доводит 01.5);
  - `overrides` подключаются последними с `allowOverride(true)` — для фейков `VideoInfoExtractor`,
    `VideoDownloader`, `YtDlpService`.
- **Testcontainers.** Один контейнер `postgres:16-alpine` на JVM (как `db` в `docker-compose.yaml`):
  singleton `PostgresTestContainer` в `java-test-fixtures` модуля `server:infra`
  (`src/testFixtures/kotlin`); `server:app` подключает `testImplementation(testFixtures(projects.server.infra))`.
  Изоляция между спецификациями — отдельная БД или `TRUNCATE`; выбор исполнителя, записать в notes.
  С этой стадии Docker обязателен для `./gradlew build`.
- **Снимок API-поверхности.** `ApiSurfaceTest` в `server:app`: живое дерево роутинга → строки
  `METHOD path`, отсортированные, точное равенство с `server/app/src/test/resources/api-surface.txt`.
  Guard на непустоту по фактическому числу роутов (число — в notes).
- **Golden JSON.** `api/contract/src/jvmTest/resources/golden/*.json` для `JobDto`, `RuleDto`,
  `ChannelDto`, `PreviewResponseDto`, `SystemSettingsDto`, `WorkspaceDto`, `ApiErrorDto` — со всеми
  вариантами sealed-иерархий внутри. Проверка двусторонняя через `apiJson`:
  `encode(obj) == golden` и `decode(golden) == obj`. Объекты строятся object mothers в тесте.
- **JSONB-фикстуры.** Для каждого `*Pm`, который пишется в `jsonb`, и каждого его варианта JSON
  генерируется **текущими** сериализаторами один раз в этой стадии и коммитится в
  `server/infra/src/test/resources/jsonb-fixtures/`. Тест вставляет строки сырым SQL и читает их
  через репозитории. После этой стадии фикстуры не перегенерируются (только добавляются новые).
- **Тест миграций.** Пустая БД → путь старта из `DatabaseFactory` → Flyway `validate()` без ошибок;
  применены все файлы из `db/migration` (сейчас 8, `V1…V8`), guard: не меньше 8. Тест не должен
  ломаться от будущей `V9`.
- **Round-trip репозиториев.** Все 6 (`ChannelRepositoryImpl`, `JobOutputRepositoryImpl`,
  `JobRepositoryImpl`, `RuleRepositoryImpl`, `VideoInfoCacheImpl`, `WorkspaceRepositoryImpl`) и
  `SystemSettingsHolder`: save → find → update → find. Вызовы обёрнуты в `ExposedTransactionRunner`,
  чтобы тесты пережили удаление `dbQuery` в 01.8 без правок.
- **Роут-тесты.** `testApplication { application { module(testConfig, startBackgroundServices = false, overrides = fakes) } }`
  + Testcontainers + `devMode = true` (`X-Telegram-Init-Data: dev`):
  - happy path по каждой группе: workspaces, preview, jobs, rules, channels, system;
  - 401 без заголовка;
  - ресурс чужого workspace (job, rule, channel) → текущий код (ожидается 404);
  - `POST /workspaces` с битым slug → текущие `400` и тело `{"error": …}` (не `ApiErrorDto`, так и
    остаётся навсегда);
  - `POST /workspaces` с занятым slug → текущее поведение (200, вызывающий стал `MEMBER`);
  - битый UUID в пути (`jobId`, `ruleId`) и в теле → текущий 500; ожидание поменяет 01.5 (G10).
- **Разовый эксперимент (не коммитить как тест).** Внутри `ExposedTransactionRunner.inRwTransaction`
  сделать запись через репозиторий (он откроет свой `dbQuery`), затем бросить исключение: откатилась
  ли запись? Результат — в notes; 01.8 опирается на него.

## Work

1. Вынести `module()`, перевести `main`.
2. `java-test-fixtures` + `PostgresTestContainer`.
3. Тест миграций, round-trip репозиториев, JSONB-фикстуры.
4. Golden JSON в `api:contract`.
5. `ApiSurfaceTest` и `api-surface.txt`.
6. Роут-тесты с фейками.
7. Эксперимент с вложенной транзакцией.

## Checks

```bash
./gradlew build            # Docker должен быть запущен
grep -rn 'configureApplication' server   # пусто
```

Проверки на красное (сделать → убедиться → откатить; записать в notes):

- переименовать путь любого роута → `ApiSurfaceTest` красный;
- переименовать поле любого `*Pm` → тест JSONB-фикстур красный;
- поменять `@SerialName` в любом DTO → golden-тест красный.

## Done when

- Все перечисленные тесты есть и зелёные; число роутов, число новых тестов и результат эксперимента
  записаны в notes.
- `main` вызывает `module`, `configureApplication` не существует.
